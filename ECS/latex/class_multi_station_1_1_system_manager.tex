\doxysubsection{Detailed Description}
Owns one module per C++ type and runs its system lifecycle. 

\doxylink{class_multi_station_1_1_system_manager_a60ea867119c4cd7dbc52d21ff365fdef}{Add\+Module()} constructs and registers modules without initializing them. \doxylink{class_multi_station_1_1_system_manager_ac9e288c1066ed06d5feab46d721f6839}{Init\+Modules()} initializes pending modules in registration order. Only initialized modules receive system callbacks and frame updates. \doxylink{class_multi_station_1_1_system_manager_a7bbd5490664de7f8831940cf016dbc8e}{Fini\+Modules()} shuts down and deletes all modules in reverse registration order; the destructor calls it automatically.

Typical usage\+: \doxylink{class_multi_station_1_1_system_manager_a60ea867119c4cd7dbc52d21ff365fdef}{Add\+Module$<$\+T$>$()}, \doxylink{class_multi_station_1_1_system_manager_ac9e288c1066ed06d5feab46d721f6839}{Init\+Modules()}, On\+Update(dt) each frame, then \doxylink{class_multi_station_1_1_system_manager_a7bbd5490664de7f8831940cf016dbc8e}{Fini\+Modules()} or destruction. Modules added later remain pending until the next explicit \doxylink{class_multi_station_1_1_system_manager_ac9e288c1066ed06d5feab46d721f6839}{Init\+Modules()} call.

\begin{DoxyWarning}{Warning}
Not thread-\/safe. From module/system callbacks, do not add or remove modules, initialize/finalize modules, or recursively call \doxylink{class_multi_station_1_1_system_manager_ad95e5242d219c0e0be48b4e77d027e21}{On\+Update()}. 
\end{DoxyWarning}

For initialized modules, calls On\+Disable() if last processed as enabled, then On\+Dettach() and Fini(context). Uninitialized modules receive no callbacks. Every module is deleted and all corresponding metadata erased. Calling this on an empty manager has no effect. New modules may be added and initialized afterward; finalized instances are not retained.

Initializes all pending modules in registration order. 

Calls module Init(context), then system On\+Attach(). After attachment, records Is\+Enable() and calls On\+Enable() only if that flag is true. Initially disabled systems receive neither On\+Enable() nor On\+Disable(). Already initialized modules are skipped, so repeated calls initialize only modules added since the previous call.

\end{DoxyPrecond}

Do not call from module or system callbacks.

void Multi\+Station\+::\+System\+Manager\+::\+On\+Update (\begin{DoxyParamCaption}\item[{float}]{dt}{}\end{DoxyParamCaption})\hspace{0.3cm}{\ttfamily [noexcept]}}



Processes enabled-\/state changes, then updates enabled systems. 

First checks every system\textquotesingle{}s Is\+Enable() flag and calls On\+Enable() or On\+Disable() when it differs from the last processed state. A second pass calls On\+Update(dt) for systems processed as enabled. Both passes run sequentially in registration order. Uninitialized modules are skipped in both passes.


\begin{DoxyParams}[1]{Parameters}
\mbox{\texttt{in}}  & {\em dt} & Frame delta time forwarded unchanged to each enabled system. \\
\hline
\end{DoxyParams}
\begin{DoxyNote}{Note}
Set\+Enable() changes are processed during the state-\/check pass. Changes made during system \doxylink{class_multi_station_1_1_system_manager_ad95e5242d219c0e0be48b4e77d027e21}{On\+Update()} callbacks take effect on the next manager update, including changes to systems that have not updated yet. 

No fixed timestep updates are performed. 
\end{DoxyNote}
