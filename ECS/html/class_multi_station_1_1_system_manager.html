Detailed Description

Owns one module per C++ type and runs its system lifecycle.

AddModule() constructs and registers modules without initializing them. InitModules() initializes pending modules in registration order. Only initialized modules receive system callbacks and frame updates. FiniModules() shuts down and deletes all modules in reverse registration order; the destructor calls it automatically.

Typical usage: AddModule<T>(), InitModules(), OnUpdate(dt) each frame, then FiniModules() or destruction. Modules added later remain pending until the next explicit InitModules() call.

Warning
Not thread-safe. From module/system callbacks, do not add or remove modules, initialize/finalize modules, or recursively call OnUpdate().

◆ FiniModules()

void MultiStation::SystemManager::FiniModules ( void )
noexcept

Shuts down, deletes, and unregisters every module in reverse order.

For initialized modules, calls OnDisable() if last processed as enabled, then OnDettach() and Fini(context). Uninitialized modules receive no callbacks. Every module is deleted and all corresponding metadata erased. Calling this on an empty manager has no effect. New modules may be added and initialized afterward; finalized instances are not retained.

Postcondition
The manager is empty; all borrowed module pointers are invalid.
Warning
Do not call from module or system callbacks.

◆ InitModules()

void MultiStation::SystemManager::InitModules ( void )
noexcept

Initializes all pending modules in registration order.

Calls module Init(context), then system OnAttach(). After attachment, records IsEnable() and calls OnEnable() only if that flag is true. Initially disabled systems receive neither OnEnable() nor OnDisable(). Already initialized modules are skipped, so repeated calls initialize only modules added since the previous call.

Precondition
Each module must provide a valid GetSystem() after Init() returns.
Warning
Do not call from module or system callbacks.

◆ OnUpdate()

void MultiStation::SystemManager::OnUpdate ( float dt)
noexcept

Processes enabled-state changes, then updates enabled systems.

First checks every system's IsEnable() flag and calls OnEnable() or OnDisable() when it differs from the last processed state. A second pass calls OnUpdate(dt) for systems processed as enabled. Both passes run sequentially in registration order. Uninitialized modules are skipped in both passes.

Parameters
[in]dtFrame delta time forwarded unchanged to each enabled system.
Note
SetEnable() changes are processed during the state-check pass. Changes made during system OnUpdate() callbacks take effect on the next manager update, including changes to systems that have not updated yet.
No fixed timestep updates are performed.
